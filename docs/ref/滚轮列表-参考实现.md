## 一、它为什么丝滑 —— 三个关键点（我此前全做错了）

### ① 整条列表只用一个 transform（刚性体）
```js
wheelItemsRef.current.style.transform =
  `translateZ(${-radius}px) rotateX(${itemAngle * normalizedScroll}deg)`
```
**滚动 = 改这一个 transform**。没有任何一条是独立运动的 → **不可能互相碰撞**。
（我前面 6 个版本都在"每条各自算位置、各自播过渡"，方向就是错的。）

### ② 用 rAF 手动插值，**不用 CSS transition**
```js
const animateScroll = (start, end, duration, onComplete) => {
  const t0 = performance.now()
  const tick = (now) => {
    const p = (now - t0) / 1000 / duration
    if (p < 1) {
      scrollRef.current = scrollTo(start + easeOutCubic(p) * (end - start))
      requestAnimationFrame(tick)
    } else { scrollTo(end); onComplete?.() }
  }
  requestAnimationFrame(tick)
}
```
- `easeOutCubic = p => (p-1)**3 + 1`
- **全程只有一个浮点数在变**（`scrollRef.current`）—— 这是"丝滑"的根本
- 我用的 CSS transition 会：中断后重排、SVG 上不走进合成层、多步时反复重启 ✗

### ③ 无限循环 = **多拷贝 + 取模**，所以归位是不可见的
```js
const normalizeScroll = (s) => ((s % n) + n) % n
// 列表构建时前后各补 quarterCount 条，使"相隔 n 的条看起来完全一样"
```
取模会跳 ✗，但因为**两端有拷贝**，跳过去的位置和跳之前**画面一模一样** ✓ → 看不见。

### ④ 顺带的两个细节
- **滚轮限流**：`if (now - lastWheelTime < 100) return` —— 最快 10 步/秒 ✓（比"跨多步"更稳）
- **3D 圆柱**：`itemAngle = 360/count`、`radius = itemHeight / tan(itemAngle)`，
  每条的 `transform: rotateX(-itemAngle*index) translateZ(radius)`
  → 这就是"贴在圆环边上"的观感来源（**轻微 rotateX 即可，不必是完整圆柱**）

## 二、我们的落地方式（下一步要做）

保留 lab 已有的视觉（左贴盘缘的荧光胶囊、5 条聚焦窗、三级递减、两端模糊、时长嵌在条里），
**只替换运动层**：

1. 所有条排进**一个 `<g>`**，位置固定
2. 每条加一个**小的 `rotateX`**（按格数）→ 得到"贴弧"的扇形观感
3. 滚动：改这个 `<g>` 的**一个 transform**，值由 **rAF 插值**驱动（不是 transition）
4. 两端各补若干拷贝 → 取模归位不可见
5. 滚轮限流 100ms

⚠️ 关键：**位置只能由那一个浮点数派生**。任何"某条自己算自己的位置"都会重新引入重叠。
