## 1. 产品背景（决定了一切设计取舍）

- 一款 **24 小时不间断的时间追踪**产品，三端共用一份数据：
  **桌面悬浮组件（Electron，约 260×380 透明窗口）· 网页版 · 微信小程序**
- 桌面组件是主战场：正中一个 **152px 的圆形表盘**
- **产品定义（用户拍板，不要再挑战）**：
  - **没有"停止"** —— 时间永远在走，所以**不存在"空档"**
  - 切换分类才是主路径；"暂停/停止"只是多端能力未齐时的临时妥协
  - **无感记录**：产品要**简单再简单**，交互不该有存在感
  - 数据流向：结构化日志 → Google Doc → NotebookLM

## 4. 已查清的技术结论（别再重走）

### 4.1 几何不可能三角（★ 最重要，背景）
在 **152px 的盘、一屏 5 条、文字横排**这三个约束下：
**"左边界弯 + 右边界也弯 + 横向装下文字"数学上不能同时成立。**
- 左边界 = 盘缘弧（半径 72）
- 右边界若用同心弧 → 半径 = 72 − 条宽(≈64) = **8px** → **半径 8 的弧在 30px 高度上就是直线**
- 想让内弧明显（半径 40）→ 条只剩 **32px 宽** → 装不下「工作 2:15」

**结论**：能看见的"形变"只能来自**位置 + 尺寸的连续变化**，不能来自"形状被掰弯"。

### 4.2 v16.5 定稿几何（当前基线参数）
```
R=76  SAFE=4  LIMIT=72  ROW_H=24  VISIBLE=2  COPIES=2  N=7
条高 LV：中心 24 / 次 20 / 更外 16 / 消失端 14
最外圈（a≤2.5 → 中心 ±60）+ 半高 8 = 68 ≤ 72
→ 所有可见条任意滚动位四角都在圆内：弹出 / 裁切在数学上消失
```
- `xL = -sqrt(72² − yOuter²)`（左端按 yOuter 贴弦）；`w = wantW` 由 `fitsAll`（+1e-6 容差）while 递减至 >16
- 文字：`t1 = xL+6`、`t2 = xL+w-6`（end-anchor）；`sel = ((round(pos)+VISIBLE)%N+N)%N`、初始 `pos=-VISIBLE`
- `#core` 焦点名 `translate(calc(-50%+14px),-50%)`（偏右避开条内时长）；确认 900ms 后名称变绿 + `scale(1.08)`

### 4.3 运动层（★ v16.7 目标追赶循环，当前基线）
参考 **`ncdai/react-wheel-picker`**（MIT · 779★ · Vercel OSS）—— "iOS-like wheel picker with smooth inertia scrolling and infinite loop support"。三个要件：
1. **整条列表只用一个 transform / 一个浮点数 pos** —— 滚动就是改这一个值，没有一条独立运动 → 不可能碰撞
2. **用 rAF 手动插值，不要用 CSS transition** —— CSS transition 在 SVG 上**不走合成层**，且快速滚动会被**反复重启** → 就是"卡"的来源
3. **无限循环 = 多拷贝 + 取模** —— 取模会跳，但两端有拷贝，跳过之后画面一模一样 → 看不见

**v16.7 具体做法（用户验收的滑动过渡）**：
- 任何输入（滚轮 / 键盘 / 点击）**只更新 `goal`**，不直接挪位置
- rAF 常驻循环每帧：`pos += (goal − pos) * LERP`（LERP=0.22，1 格 ≈ 0.3s 滑到位）
- 事件停止后 `vel` 接管惯性（FRICTION=0.90、STOP_VEL=0.02、MAX_VEL=1.0），滑尽落格
- 滚轮 / 键盘 / 点击三路都走平滑滑动——"直接跳到下一个"的观感来源 = 事件一次性到位、无中间帧，已根治

**铁律**：**位置只能由那一个浮点数派生。** 任何"某条自己算自己的位置"都会重新引入重叠。

**★ 目标连续化（2026-10-15 真机修复，勿回退）**：`pickGoal` **不能**直接写 `gi - VISIBLE`（绝对索引）——
那样「末项 → 首项」的目标会从 -(n-1) 格整圈回跳，rAF 把带子倒着滑回去，观感是"弹回第一个"。
正确做法 = `arcFoldGoal(pickGoal, gi - VISIBLE, n)`：把新目标折到与**当前目标同圈、最近的一层**，
每一步只推进 ±1 格；环上取模只发生在渲染层（`frac = pos mod n`）。
验证锁：verify_arc_pick.py 的「fold 连续性」断言（跨首尾/双向/多整圈，Δ 恒 ±1 且落定仍对准焦点项）。

### 4.4 外观（v16.6 连续插值，当前基线）
- 三档离散跳变 → 随偏移 `a=|物理偏移|` 连续插值：`paramsAt(a)` 在 LV 表相邻档线性插值
- LV 插值表（a=0/1/2/3 消失端）：`{h:24,nm:13,du:11,op:1,blur:0} / {h:20,nm:11,du:9,op:.94,blur:0} / {h:16,nm:10,du:8.5,op:.6,blur:1.6} / {h:14,nm:9,du:8,op:.3,blur:2.6}`
- 文字淡出 `fadeT=(a-0.9)/0.6`；条收窄 `shrinkT=(a-1.5)/0.3` → 纯色窄条 26
- 落格 `easeOutBack` 微过冲（≈2.4px）
- 性能：删掉每帧重写的 clipPath，blur/op/字号全部量化记忆化（值没变就不写）
- **★ 确认进度线布局（2026-10-15 真机修复，勿回退）**：选中条底部那条白线的几何走纯函数
  `arcProgLayout(xL,h,w,prog)`（PURE 块内）：线顶 = `h/2-4.0`、高 2.4、线底 = `h/2-1.6`、
  左右内衬 7px。旧口径线顶 `h/2-5.5` 与 13px 文字的 em 盒底（`h/2-6.5`）只差 0.7px，
  反锯齿渲染后与文字粘连（用户真机反馈"白线和文字互相遮罩"）。验证锁：verify_arc_pick.py
  的 `prog-*` 断言（与文字 em 留量 ≥1px、离条底 ≥1px、不越出两端圆头）。

**其它已踩的坑**：
- 用脚本整段替换代码 → **连着删掉了不该删的 `setAttribute('d')` / `('fill')`** ✗
  → 现象是"有字无条""条全黑"，而且**不报错**。**替换后必须逐行核对。**
- `d` 完全不取模 → 滚到末尾**列表变空**（只剩 1～2 条甚至全空）
- 位移写成**增量**（`yc - 上次的yc`）却又按新位置重绘 → 二者叠加 → **上下抽风**
- 每次重绘无条件重写 `d`/`fill`/`blur` → 反复栅格化 → **卡**（已加记忆：值没变就不写）
- **v16.8 弦宽占满 → 视觉否决**；**v16.7 滑动过渡 → 已验收**（两条为最新基线结论）

## 6. 验证手段（★ 重要：脚本已入库，不依赖浏览器）

**`playwright-cli` 连本地/线上站点都极不稳定**（会话反复丢失，历史上失败十几次）。
**可靠替代：把纯函数抽出来，用 node 直接跑。**

- **`site\_verify\verify_arc.py`**（已入库，接手直接用）：
  - ① 抽出 `<script>` 做 `node --check` 语法检查 ② 纯函数穷举
  - 当前口径 = v16.7：**56 个 frac 采样 × 14 条 = 287 行断言，全部 PASS**
  - 断言覆盖：四角 `fitsAll` / 无穿心（xL 贴弦）/ `w>16` / 文字余量 gap / **有符号 dRaw** 垂直间距（曾误用绝对值 a 导致 350 个假 FAIL）/ 分类不重复 / `yOuter>LIMIT` 零触发
  - 跑法：`python site\_verify\verify_arc.py`（依赖 node 在 PATH）
- **`site\_verify\verify_arc_pick.py`**（2026-10-15 新增，**正式组件迁移版，改弧排几何必跑**）：
  - ① app.js 整文件 `node --check` ② 抽取 `ARC-PICK:PURE` 标记块 + `fmtMS` + `ARC_LERP` 穷举
  - 当前口径：**5412 行断言，全部 PASS**；n ∈ {1,2,3,4,5,6,7,8,10,15,20,31} × 数据形态（长名/ASCII/大数据/全幽灵/`__none__`/`__add__`）× frac 全相位
