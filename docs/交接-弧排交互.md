## 1. 产品背景（决定了一切设计取舍）

- 一款 **24 小时不间断的时间追踪**产品，三端共用一份数据：
  **桌面悬浮组件（Electron，约 260×380 透明窗口）· 网页版 · 微信小程序**
- 桌面组件是主战场：正中一个 **152px 的圆形表盘**
- **产品定义（用户拍板，不要再挑战）**：
  - **没有"停止"** —— 时间永远在走，所以**不存在"空档"**
  - 切换分类才是主路径；"暂停/停止"只是多端能力未齐时的临时妥协
  - **无感记录**：产品要**简单再简单**，交互不该有存在感
  - 数据流向：结构化日志 → Google Doc → NotebookLM

## 2. 用户的完整需求（原话，按时间顺序）

> **定方向**
> 1. "把选项都框在这个圆形常驻显示范围里面做成类似手表的交互，贴在左侧圆弧形排列，被选的那个放大"
> 2. "常驻表盘的形式不要动"
> 3. "字体还是黑色的完全看不见"
> 4. "保留那个荧光条的效果，是放大那个荧光条"

> **定形态**
> 5. "不是淡出，依然是一列的形式，排列在左侧贴着边缘，被选中的放大一点，没选中的缩小一点"
> 6. "让备选的和上下各一个项目出现名称，其他的不出现名称只有颜色，并用模糊的效果遮盖一下，同时只出现 5 个标签显示就好，然后被选中的那个更大一些，上下两端逐渐缩小"
> 7. "荧光条再大一点，可以所有显示的待选一起撑满表盘，把时间信息也弄在荧光条里面，现在的太小、太简陋了，那个文字也不许超出荧光条的范围"
> 8. "把左侧完全贴紧表盘边缘，并让待选项的荧光条会随之形变以贴合表盘边缘"
> 9. "是改变荧光条的形状，贴在左侧圆环上面……左侧随圆环形变。图中我描红的这些位置不要空着，让荧光条的颜色填满"
> 10. "永不超出圆环范围"

> **定手感**
> 11. "高速滚动的时候，这些条会堆到一起，看着很影响交互体验，你做成连续的，不会来回跳跃的形式"
> 12. "这个动效卡卡的，你做的流畅一点，另外在交互过程中会超出圆环显示范围"
> 13. "高速滚动还是会出现这种问题，重写吧，**用现在桌面组件版本的交互效果抄一下，桌面那个组件的列表滚动就很丝滑**"
> 14. "**自己去 github 上面找别人的项目，抄别人的代码去**"（用户明确禁止再自己发明）

**归纳成 6 条硬要求**：
① 全部框在 152px 圆内，**永不超出** ② 一列，**左端贴盘缘** ③ **只显示 5 条**，选中最大、两端递减
④ 选中 + 上下各一条显示**名称与时长**，更外的**只有颜色 + 模糊** ⑤ 荧光条要**撑满**、文字**不溢出条**
⑥ **滚动必须丝滑、连续、零重叠**（快速滚动是重点场景）

## 4. 已查清的技术结论（别再重走）

### 4.1 几何（★ 最重要）
在 **152px 的盘、一屏 5 条、文字横排**这三个约束下：
**"左边界弯 + 右边界也弯 + 横向装下文字"数学上不能同时成立。**
- 左边界 = 盘缘弧（半径 72）
- 右边界若用同心弧 → 半径 = 72 − 条宽(≈64) = **8px** → **半径 8 的弧在 30px 高度上就是直线**
- 想让内弧明显（半径 40）→ 条只剩 **32px 宽** → 装不下「工作 2:15」

**结论**：能看见的"形变"只能来自**位置 + 尺寸的连续变化**，不能来自"形状被掰弯"。
（若一定要形状明显弯，必须动尺寸：条加高到 45 / 盘缩到 100 / 盘放大到 190）

### 4.2 运动层（★ 抄这里）
参考 **`ncdai/react-wheel-picker`**（MIT · 779★ · Vercel OSS）—— "iOS-like wheel picker with smooth inertia scrolling and infinite loop support"。三个要件：
1. **整条列表只用一个 transform** —— 滚动就是改这一个值，没有一条独立运动 → 不可能碰撞
2. **用 rAF 手动插值，不要用 CSS transition** —— `easeOutCubic`，全程只有一个浮点数在变
   （CSS transition 在 SVG 上**不走合成层**，且快速滚动会被**反复重启** → 就是"卡"的来源）
3. **无限循环 = 多拷贝 + 取模** —— 取模会跳，但两端有拷贝，跳过之后画面一模一样 → 看不见
   （附带：它的滚轮**限流 100ms**，最快 10 步/秒）

**铁律**：**位置只能由那一个浮点数派生。** 任何"某条自己算自己的位置"都会重新引入重叠。

## 5. 死路清单（这 9 版走过的，别重复）

| # | 做法 | 结果 |
|---|---|---|
| v1–v2 | 圆点弧排 → 荧光条 | 太小、太简陋 |
| v3 | 一列随圆边弯曲 | 形状对，无聚焦层次 |
| v4 | 5 条聚焦窗 + 模糊分级 | 层次对了 |
| v5 | 加大撑满 + 时长入条 | 尺寸对了（**用户认可"就是这样"**） |
| **v6** | **左端伸到圆外、靠圆形裁切塑形** | ✗ 观感变成"**从左侧外面弹出来**" |
| v8 | 左边界画成盘缘弧（SVG path） | ✓ 新月空隙填满，但右边仍直线 → "像切了一块贴上去" |
| v9 | 元素复用恢复动效 | ✓ 动效回来 |
| v10 | 修 POOL 缺失崩溃 | ✓ 恢复渲染 |
| **v11–13** | **每条各自算位置 + CSS transition** | ✗ **快速滚动必然堆叠**（途中相撞）；反复打补丁治不了 |
| v14 | 整条带子刚性平移 | ✓ 结构上不再重叠 |
| **v15（当前）** | **运动层换 rAF 插值 + 限流 100ms** | 待人工确认观感 |

**其它已踩的坑**：
- 用脚本整段替换代码 → **连着删掉了不该删的 `setAttribute('d')` / `('fill')`** ✗
  → 现象是"有字无条""条全黑"，而且**不报错**。**替换后必须 `git diff` 逐行核对。**
- `d` 完全不取模 → 滚到末尾**列表变空**（只剩 1～2 条甚至全空）
- 位移写成**增量**（`yc - 上次的yc`）却又按新位置重绘 → 二者叠加 → **上下抽风**
- 每次重绘无条件重写 `d`/`fill`/`blur` → 反复栅格化 → **卡**（已加记忆：值没变就不写）

## 6. 验证手段（★ 重要：不要依赖浏览器）

**`playwright-cli` 连本地/线上站点都极不稳定**（会话反复丢失，本条对话里失败了十几次）。
**可靠替代：把纯函数抽出来，用 node 直接跑。** 例：
```bash
# 抽出 <script> 做语法检查
python -c "import io,re;s=io.open('site/lab-arc.html',encoding='utf-8').read();m=re.search(r'<script>(.*?)</script>',s,re.S);io.open('tmp.js','w',encoding='utf-8').write(m.group(1))"
node --check tmp.js
# 把 capsulePath / 定位函数复制进一个 tmp.js，喂真实参数，打印结果
```
**验收清单（每次改完都跑一遍）**：
① 可见条数恒为 5 ② **四角都在圆内**（`fitsAll`）③ 文字不溢出（`scrollWidth ≤ clientWidth`）
④ **滚动过程中的最小间距 = ROW_H**（刚性体证明）⑤ 每个分类在**可见期间**位移 ≤ 1 格/步
